## 一、项目概述

### 1.1 项目目标
为越野跑爱好者提供一站式赛事管理平台，核心解决跑者在比赛日的焦虑管理和完赛记录分享需求。

### 1.2 MVP功能范围

| 模块 | 功能 | 说明 |
|------|------|------|
| **赛程当日规划** | 装备清单 | 强制装备/建议装备/查漏补缺 |
| | 通勤方式 | 起点导航/停车指引/公共交通 |
| | 补给站信息 | 位置、距离、海拔、关门时间 |
| | 天气预报 | 温度、降水概率、风速 |
| **我的比赛** | 完赛记录 | 成绩、排名、照片、轨迹 |
| | 参赛地图 | 交互式地图展示 |
| | 轨迹图片生成 | 可分享社交图片 |
| **赛事发现** | 赛事搜索/收藏 | 筛选条件 |
| **ITRA联动** | 积分同步 | 表现指数、历史记录 |
| **赛事群聊** | 赛事聊天室 | 简化版赛博小镇 |

## 二、功能模块设计

### 2.1 赛程当日规划

**核心价值**: 比赛当天一站式信息聚合，降低赛前焦虑

#### 2.1.1 装备清单

- **强制装备**: 赛事要求的必带装备（号码簿、GPS手表、救生毯等）
- **建议装备**: 根据天气/地形建议的装备（登山杖、手套、防晒霜等）
- **查漏补缺**: 基于距离/天气/爬升智能提醒可能遗漏的装备

**交互流程**:
1. 用户选择参赛赛事
2. 系统展示装备清单（含强制/建议分类）
3. 用户逐项勾选确认
4. 未勾选项高亮提醒

#### 2.1.2 通勤方式

- **起点导航**: 一键跳转高德导航到起点
- **停车指引**: 附近停车场位置和距离
- **公共交通**: 公共交通路线建议（如有）

#### 2.1.3 补给站信息

| 字段 | 说明 |
|------|------|
| 站名 | 补给站名称 |
| 距离 | 起点到该站距离 |
| 海拔 | 该站点的海拔 |
| 补给类型 | 水/运动饮料/能量胶/食物/医疗服务 |
| 关门时间 | 该站点的关门时间节点 |

#### 2.1.4 天气预报

- 显示比赛当日的天气预报
- 数据来源: 高德天气API / 第三方天气API
- 展示: 温度、降水概率、风速、风向、体感温度

### 2.2 我的比赛

**核心价值**: 完赛记录管理 + 可分享炫酷轨迹图片

#### 2.2.1 完赛记录

**包含字段**:
- 赛事名称、日期、地点
- 距离、爬升、关门时间
- 完赛时间、排名（总排名/分龄组排名）
- 轨迹文件（GPX）
- 照片关联
- 完赛证书（可选）

#### 2.2.2 参赛地图展示

- 在App内以交互式地图形式展示轨迹
- 标记点: 起点、终点、补给站（可点击查看详情）
- 轨迹颜色: 可根据海拔/速度渲染渐变
- 可缩放、拖拽

#### 2.2.3 轨迹图片生成

**图片内容**:
- 赛事名称 + 日期
- 轨迹地图（带标记点）
- 关键数据: 距离、爬升、完赛时间
- 用户ID/完赛纪念

**生成方式**:
- Python Pillow + Matplotlib 生成静态图片
- 或 Go + CairoSVG 库

**分享**: 支持保存到相册 / 直接分享到微信/朋友圈

### 2.3 赛事发现

- 按距离/日期/难度/ITRA积分筛选
- 赛事详情页: 路线图、爬升图、ITRA评分
- 收藏赛事 + 设置提醒

### 2.4 ITRA联动

- 用户授权同步ITRA账户
- 展示: ITRA积分、表现指数
- 完赛后预测积分变化

### 2.5 赛事群聊

- 每个赛事有对应群聊
- 简化版赛博小镇替代方案
- 功能: 文字聊天、查看参赛者列表

## 三、数据模型

### 3.1 核心实体

```
User (用户)
├── id, nickname, avatar
├── ITRA账号关联
└── 隐私设置

Race (赛事)
├── id, name, date, location
├── distance, elevation
├── difficulty, ITRA_points
├── route_gpx_url
└── aid_stations[]

Result (完赛记录)
├── id, user_id, race_id
├── finish_time, ranking
├── gpx_url, photos[]
├── generated_image_url
└── status

AidStation (补给站)
├── race_id, name
├── distance, elevation
├── supplies[], close_time

Equipment (装备清单)
├── race_id, name
├── is_mandatory
└── category
```

## 四、API设计（概要）

### 4.1 用户模块
- `POST /api/v1/users/register` - 注册
- `POST /api/v1/users/login` - 登录
- `GET /api/v1/users/me` - 获取当前用户信息

### 4.2 赛事模块
- `GET /api/v1/races` - 搜索赛事（支持筛选）
- `GET /api/v1/races/:id` - 赛事详情
- `POST /api/v1/races/:id/favorite` - 收藏赛事

### 4.3 当日规划模块
- `GET /api/v1/races/:id/plan` - 获取当日规划数据
- `GET /api/v1/races/:id/equipment` - 获取装备清单
- `POST /api/v1/races/:id/equipment/check` - 更新装备勾选状态

### 4.4 完赛记录模块
- `GET /api/v1/results` - 我的比赛列表
- `POST /api/v1/results` - 创建完赛记录
- `GET /api/v1/results/:id` - 记录详情
- `POST /api/v1/results/:id/image` - 生成轨迹图片

### 4.5 地图服务
- `GET /api/v1/map/tile/:z/:x/:y` - 地图瓦片

## 六、注意事项

- MVP阶段不引入3D渲染，保持技术复杂度可控
- 轨迹图片生成作为独立Python微服务，避免Go图像处理短板
- 地图数据优先对接高德，逐步扩展数据源
- 离线缓存考虑：已缓存的赛事信息和轨迹可在无网时展示
